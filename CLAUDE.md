# Stock gifts demo: project notes

Context for an AI coding assistant working on this project. Update this file
when the workflow or a fact changes.

## What this is

A static HTML dashboard tracking ETF gift purchases for four fictional kids.
Each gets about $100 CAD in an S&P 500 ETF on their birthday and at
Christmas; at 18 the holdings are handed over. `index.html` is the site;
`portfolio_data.json` is the source of the holdings and transactions;
`scripts/refresh_prices.py` updates prices and is run by the GitHub Actions
workflow at `.github/workflows/refresh-prices.yml`.

This is a public demo of a private family dashboard. The kids, their birth
dates and their gifts are invented. The prices are real.

## Price data

Two price files plus a baked-in fallback:

- `history.json`: the daily series the over-time chart draws. Shape:
  `{generatedAt, dates:[...], prices:{ticker:[aligned closes]}}`.
  `refresh_prices.py` merges the last `HISTORY_PERIOD` (three months) of
  closes into it on every run, so a gap left by a skipped run is backfilled
  and old data is never lost. `loadPriceHistory()` in `index.html` fetches
  it at boot and replaces the baked `PRICE_DATES` and `PRICE_HISTORY`
  (declared with `let`) before anything renders.
- `prices.json`: one latest quote per ticker, for the live "today" point at
  the right edge of the chart. Written by the same run.
- The baked `PRICE_DATES` and `PRICE_HISTORY` in `index.html` end
  2026-05-15 and are the fallback if `history.json` is missing or
  malformed. They are not updated; `history.json` is the source of truth
  after that date.

If the chart shows a straight line from May 2026 to today, the Action has
not run since the fork. Trigger it from the Actions tab ("Refresh prices",
"Run workflow"). The workflow needs `contents: write`, which it declares.

## Hosting

GitHub Pages serves `main` from the repository root. Every path in the page
is relative so it works under the `/stock-gifts-demo/` subpath. Pushing to
`main` deploys.

## Transaction dates

Every gift is dated on its occasion, the kid's birthday or Christmas, never
the day the shares were bought. `txDate(tx)` treats a transaction dated in
the future as landing today, so an early purchase shows on the chart at
once and the stored date stays on the occasion. `nextGiftDate(kid)` skips
an occasion whose gift is already bought, skips occasions past the 18th
birthday and returns `null` when no gift is left.

## Features, in the order they appear in the file

- Group filter (the Show select): group ids are keyed in CSS
  (`.pill-select[data-value=...]`, `.filter-row ... [data-filter=...]`),
  in the select's options, in the leaderboard's fallback list and in the
  two filters. Add a group in all of those places.
- Handoff countdown: `countdownText()`, refreshed each minute.
- Projection fan chart on kid pages: 4, 8 and 12 percent paths to the 18th
  birthday, one gift added at every future occasion (`projectSeries()`).
- PWA: `manifest.json`, `sw.js` (network-first for the page and same-origin
  JSON, cache-first for CDN libraries). Bump `CACHE` in `sw.js` to
  invalidate. Icons are regenerated by `python3 scripts/make_icons.py`.
- Count-up and confetti, both off under `prefers-reduced-motion`.
- Badges: `computeBadges()` from transactions and the price series. The
  `fhsa` badge is the exception: it unlocks when `kid.fhsaOpened` falls
  within `FHSA_WINDOW_DAYS` of the 18th birthday. The owner records that
  date by hand in both `DATA` and `portfolio_data.json`.
- Coming up: the next five gift occasions across all kids.
- House fund: progress toward a 20 percent down payment on
  `DATA.homeBenchmark` (CREA national average, updated by hand, never
  fetched). A kid-level `homeCity: {label, price, asOf}` overrides it.
- Birthday email template: `nameFor(kid)` is how the owner signs it.

## Code conventions

- `index.html` is the single source of truth. Inline CSS and JS, no build
  step. Preview with any static file server.
- Live price fetching tries Yahoo's v8 chart endpoint in the browser and
  falls back to `priceFallback` in `DATA.tickers`. The fallback is fine;
  the page still renders.
- Keep `DATA` in `index.html` and `portfolio_data.json` in sync by hand.
- Do not commit `__pycache__` or virtual environments (see `.gitignore`).
